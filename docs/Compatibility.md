# 兼容范围与扩展接口（0.1.5）

## 文件和补丁隔离

GUID、程序集、命名空间、Harmony owner、Lobby 标记及网络消息均使用自身身份；框架、游戏和其他 Mod DLL 仅作引用，不随包分发。只撤销自身补丁，只在处理器仍归自身所有时注销；冲突时停用自己的网络通道。

BepInEx 共享 Mono 进程，目录不是运行时沙箱。没有全局 ES3 补丁、全局 AssemblyResolve、玩家 prefab 新组件或 Mirror Weaver 改写。有限生命周期 Prefix 会控制加载、保存、连接和主动退出，其他数据入口只观察变化。目标方法必须唯一，邮件两个重载分别指定签名；共享补丁目标输出诊断。其他 Prefix 跳过原方法时，不把自身 Postfix 当成原版加载成功。

## 缓存、会话与网络

主线程只采集深复制状态、执行适配器和语义校验；编码、哈希、缓存提交及本地维护在独立后台写入器执行。每角色一个提交中和一个最新待提交请求；网络任务使用另一个有界串行队列，不占本地队列。恢复读取、校验与应用同步执行，不在后台调用 Unity 或适配器。

事件 250ms 合并，普通采集最高 1Hz，5 秒巡检捕获直接字段修改。实际内容相同时不新增版本、写缓存或发周期同步包。采集仍有主线程复制和校验开销，未作实机性能测量。

退出原因、主机身份、主机会话及授权快照持久化。主动退出仅可在同一主机会话恢复；异常退出允许跨会话恢复。主机无插件时使用 SteamID + LobbyID，LAN 主动退出后不恢复。旧缓存缺少元数据需人工选择。会话资格优先于本地/主机选择，不上传或恢复已放弃的旧缓存。

当前版本使用协议 2 和独立 ProtectionWireV2 消息身份，握手带主机会话及是否允许恢复。旧协议主机和原版主机只使用本地保护，不盲发未知消息。Steam 能力声明在处理器注册成功后发布；主机每次开房换会话标识。

完整模块落盘后才确认。发送队列和待处理网络字节各上限 32MiB，待处理任务最多 32；单模块上限 16MiB 减 64KiB，完整捕获上限 24MiB。分片每片最多 8192 字节，校验长度、顺序、哈希和超时；发送合计限速 64KiB/s。恢复空闲超时 12 秒、总时长上限 600 秒。失败时保留合格本地缓存。

角色/存档切换使用代次校验；旧回调不得改变新角色。断线清空对应发送队列并取消旧 peer 的待执行操作。原版和其他 Mod 的连接维护不改写。主机保留远端历史，不凭未知扩展候选触发自动裁剪。

## 第三方个人数据适配器

公共适配器接口保持不变：

```csharp
public interface IPlayerDataAdapter
{
    string Id { get; }
    string Version { get; }
    byte[] Capture();
    void Validate(byte[] data, string savedVersion);
    void Restore(byte[] data, string savedVersion);
}

PlayerDataAdapters.Register(adapter);
PlayerDataAdapters.NotifyChanged();
```

插件初始化后在主线程注册，可用软依赖确保时序；Id 全局唯一，最多 124 字符，只含字母数字及 . - _，Version 非空。不要分发另一份本插件 DLL。注册列表使用稳定快照，离开主线程注册或访问会拒绝；NotifyChanged 只通知，不直接采集。

Capture 必须确定、只读、包含该扩展的完整个人状态，不返回 Unity 对象。返回字节立刻复制；Validate 和 Restore 各获得独立字节副本，不能借此改变源缓存。Validate 必须完整检查格式、版本和映射，不修改游戏。Restore 在加载锁内执行，应幂等，不重复奖励、叠加余额、追加邮件或修改公共容器。

适配器异常、备份缺少现有适配器或恢复端缺少适配器时暂停，不忽略字段后声称完整成功。原版数组按实际长度采集；恢复必须布局匹配，拒绝截断。主机可原样保存扩展字节，无需安装该内容 Mod。

未因未知 Mod 存在而直接拒绝运行；物品映射和数据布局不兼容会暂停恢复。必要的专用兼容排序应由适配提供，不能依赖文件名或加载顺序。

## 待验证边界

纯核心测试没有执行 Unity、游戏程序集或真实补丁链。尚未验证具体 Mod 组合、Steam 多机、真实退出/断线/强杀和跨日。安装隔离不代表任意运行时兼容，不提供防作弊或跨世界交易原子性。

## 原版存档兼容预检

原版文件按游戏自身的前缀复制规则允许短数组、可选的空收藏/里程碑等；技能等直接替换的数组仍需匹配布局。上述兼容仅用于原版加载，独立完整快照仍要求布局一致。不兼容或运行时集合未就绪不会触发原版备份覆盖。

## 恢复生命周期（0.1.5）

Ready/AddPlayer 之前只应用菜单驻留个人数据，不访问网络生成的 ContainerManager。储藏、角色数值、派生界面、装备命令和适配器 Restore 在角色生成后、解锁前同步执行。世界日期标记也仅在最终阶段重放。各阶段检查目标，失败时保留源缓存并记录阶段。

## 原版保存诊断（0.1.5）

常规保存安全门在意外断线后禁止直接保存正在清理的角色状态；初始化未完成、恢复进行中、保护暂停分别输出具体 Warning，并按会话和原因去重。断线界面的显式保存使用下文的缓存导出事务。独立恢复缓存与原版 Player.es3 是不同的提交路径。

## 显式原版导出（0.1.5）

仅断线后点击保存返回按钮启用独立导出，不放开损坏角色的正常保存。ES3 默认配置、类型缓存和私有 ES3File 只在主线程访问，后台只读写字节和哈希。未知顶层键按类型/原始字节比对保留；无法保留的嵌入未知字段会拒绝。标准原版记录采用真实泛型 Save<T> 内存序列化，完整重读验证后才发布，不调用世界保存或玩家恢复命令。

不改变扩展适配器接口。扩展数据无通用原版位置，不会伪称已导入，其字节仍在独立缓存。原版文件并发更改、检查点落后或历史分叉时拒绝覆盖；无法保证与不遵守保存协调的第三方写入器形成跨 Mod 事务。
